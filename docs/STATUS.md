### Измеренная производительность (headless Chromium, SwiftShader, 2 vCPU)

Это **худший случай**, не показатель для реального GPU:

- генерация окружения + упаковка атласа: **~12.4 с** (из них упаковка ~7.6 с);
- генерация персонажей (7 стилей × 8 направлений × 12 кадров): **~9.7–13 с**;
- сборка одного чанка земли (canvas bake + upload 2112×1056): **~1.0–2.4 с**;
- 9 стартовых чанков: **~14 с**;
- полный старт до появления мира в headless: **~40–50 с**.

Первый кадр после welcome блокируется сборкой чанков. На реальном GPU загрузка текстур должна быть на порядок быстрее, но это **не проверено**. Приоритет PERF-01 — убрать блокировку и/или снизить стоимость.

## 2. Что не проверено или проверено частично

| Область | Статус | Комментарий |
|---|---|---|
| Второй браузерный клиент | проверено (E2E) | `tools/e2e-multiplayer.mjs` проверяет одновременное подключение двух клиентов, видимость друг друга и синхронизацию перемещения |
| PvP-урон между игроками | не проверено в браузере | Серверная логика есть, unit-тестов на PvP нет |
| Подбор/выброс/перенос лута | частично | Код есть, UI есть; сценарий с контейнером не прогнан E2E |
| Сохранение после рестарта сервера | проверено | PostgreSQL 16 локально, write-through хранение, миграции применены |
| Восстановление сессии/reconnect | не проверено | Клиент переподключается, сервер держит grace 25 с |
| Docker Compose build | проверено | `docker compose build` успешно собирает client и server |
| Docker Compose runtime | требует проверки | При первом запуске server падал: `@ashfall/shared` не был включён в бандл. Исправлено (`--external` только pg/ws/zod), нужна повторная сборка/проверка |
| Звук | не проверено | WebAudio синтез; в headless не слышно |
| Мобильные устройства | не поддерживается | Только ПК, мышь+клавиатура |
| TLS/прод | не настроено | Только HTTP dev; TLS через внешний reverse-proxy |
| Перезарядка пистолета | упрощено | Патроны списываются автоматически при выстреле, отдельной анимации reload нет |
| Баррикады/окна | не реализовано | Двери открываются/закрываются, пропсы разрушаются |
| Шум от выстрелов | реализовано частично | Зомби слышат выстрел и идут к точке, но нет визуального индикатора шума |
| LOD зомби | реализовано | AI только в радиусе 48 тайлов от игроков; состояние сохраняется |
| Мир без игроков | определено |голод/жажда и зомби не тикают без онлайн-игроков; лут не восстанавливается |
| Античит | ограничен | Сервер не доверяет координатам/урону, но нет полной защиты от aimbot/macro и т.п. |

### PERF-01 — долгий первый кадр (P0/P1)

- Сейчас ассеты генерируются синхронно в `GameScene.create()`, затем 9 чанков строятся в main thread.
- Варианты:
  1. Снизить разрешение/число вариантов текстур и кадров персонажей (но не в ущерб стилю).
  2. Паковать текстуры в атласы (сделано для окружения и персонажей).
  3. Строить чанки по одному в `requestIdleCallback`/`setTimeout`, показывать прогресс в loading.
  4. Генерировать персонажей лениво (только нужные стили) или в Web Worker (OffscreenCanvas), передавать ImageBitmap.
  5. Снизить стоимость загрузки земли: рисовать чанк в 2D canvas (сделано), но 2112×1056 upload всё ещё дорог в software GL. Можно использовать текстуру 1024×512 с тайлом 32×16 и масштабировать, либо кэшировать несколько чанков в один атлас.
  6. Заменить bottom-up bake на тайловые спрайты с batching, если это быстрее на целевом железе. **Измерять, не угадывать.**

**Инструменты:** `tools/visual-test.mjs` пишет консольные `console.time`; `window.__ashfall.game` доступен в dev; `tools/export-atlas.mjs` выгружает атласы.

### TEST-01 — нет E2E на двоих (P0)

Нужен Playwright-сценарий с двумя контекстами:
1. Оба guest-логинятся.
2. Оба видят друг друга в snapshot (проверить HUD/координаты).
3. Движение одного отражается у второго (интерполяция).
4. Игрок A атакует B → у B падает HP; при смерти B выпадает лут.
5. Оба пытаются подобрать один предмет → только один получает.
6. Перезапуск сервера → персонажи/инвентарь/лут/двери восстанавливаются.

### GAME-01 — упрощения боя/выживания

- Нет отдельной перезарядки, оружие автоматически тратит патроны.
- Нет урона по частям тела, кровотечения, инфекции, температуры.
- Голод/жажда медленные; нет UI-предупреждений (кроме баров).
- Нет баррикад, окон, ремонта.
- Нет шума шагов, визуального шума выстрела.
- Нет респавна зомби (убитые остаются мёртвыми; repopulate не реализован).
- Нет сохранения трупов; визуальные трупы живут 110 с.

### SEC-01 — безопасность прототипа

- Нет TLS, Origin-проверки WS, CSRF не актуален из-за Bearer, но CORS в dev открыт.
- Ограничение частоты сообщений — token bucket на соединение; auth — по IP.
- Нет блокировки аккаунта после серии неудач, нет 2FA, нет восстановления пароля.
- Игровые операции проверяются сервером, но полный античит не гарантируется.
- Секреты только в `.env` (не коммитится); `.env.example` содержит dev-пароли.

- `tools/visual-test.mjs` ранее мог зависать на `waitForSelector('#loading-screen.hidden')`; исправлено на `waitForFunction`.

## 5. Как воспроизвести текущее состояние

```bash
cd ashfall
cp .env.example .env
npm install
docker compose up -d db
npm run migrate
npm run dev
# открыть http://localhost:5173, войти гостем
```

Скриншоты и метрики получены через:

```bash
npm run test:visual
```

Если БД уже содержит мир со старым seed, сервер откажется стартовать. Сброс: `docker compose down -v && docker compose up -d db && npm run migrate`.

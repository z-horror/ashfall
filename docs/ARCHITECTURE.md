# Архитектура

## 1. Общая схема

```
┌──────────────────────────────┐        HTTP /api/auth/*        ┌────────────────────────────┐
│ Browser (Phaser 3 + TS)      │ ─────────────────────────────► │ Node.js HTTP               │
│  - ввод, камера, анимации    │                                │  - scrypt, sessions        │
│  - предсказание движения     │ ◄──── WebSocket JSON v1 ─────► │  - static health/world     │
│  - интерполяция сущностей    │                                └────────────┬───────────────┘
│  - HUD на HTML/CSS           │                                             │
└──────────────────────────────┘                                ┌────────────▼───────────────┐
                                                                │ Authoritative simulation   │
                                                                │  20 Hz tick, 12 Hz snaps   │
                                                                │  world, zombies, combat    │
                                                                │  inventory, AOI/chunks     │
                                                                └────────────┬───────────────┘
                                                                             │ pg (pool, tx)
                                                                ┌────────────▼───────────────┐
                                                                │ PostgreSQL 16              │
                                                                │ users/sessions/characters  │
                                                                │ items/containers/doors     │
                                                                │ props/zombies/chunks/events│
                                                                └────────────────────────────┘
```

Клиент не является источником истины. Он присылает направление движения, угол прицела и намерения (`attack`, `interact`, `pickup`, ...). Сервер сам считает позиции, коллизии, попадания, урон, смерть, дроп и изменения инвентаря. Клиентские координаты в сообщениях отсутствуют.

## 2. Технологические границы

- **shared/** — единственный источник типов протокола, констант мира, RLE и физики (`moveCircle`, `hasLineOfSight`, `inAttackArc`). Импортируется и сервером, и клиентом. Благодаря этому предсказание клиента использует ту же математику, что сервер.
- **server/** — не доверяет клиенту; вся игровая логика в памяти, БД — долговременное состояние. Тик фиксированный.
- **client/** — рендер и ввод. Не содержит секретов. Собирается Vite в статические файлы.
- **database/** — SQL-миграции, применяются раннером при старте (`MIGRATE_ON_START`).
- **tools/** — Playwright-тесты, экспорт атласов.

## 3. Мир и генерация

Параметры (`shared/src/constants.ts`):

- 128×128 тайлов, тайл 1×1 логических единиц; изометрическая проекция: `screenX=(x-y)*32`, `screenY=(x+y)*16`, тайл 64×32 px.
- 16 чанков 32×32 (4×4).
- Дороги: центры 16/48/80/112, полуширина 3; тротуары — 2 тайла от дороги.
- Блоки застраиваются детерминированно от `WORLD_SEED`: стили (кирпич/бетон/промышленный/дом), интерьеры, перегородки, двери, мебель, контейнеры.
- Пропсы: машины, деревья, кусты, фонари, знаки, заборы, мусор, кровь, ящики, бочки, мебель.
- Двери — отдельные интерактивные объекты; закрытая дверь блокирует коллизию, открытая — нет.
- Контейнеры (шкафы, холодильники, ящики, багажники, мусорные баки) получают лут лениво при первом открытии. Loot детерминирован от `seed + container.id`, затем фиксируется в БД. Повторного лута нет.
- Зомби: 5–11 на чанк, типы walker/runner/brute, стабильные ID `z:cx:cy:i`. Спавн-позиции детерминированы и не ближе 12 тайлов к точке спавна.

### Что статично, а что сохраняется

| Данные | Источник | Хранение |
|---|---|---|
| Геометрия карты, здания, стены | seed | регенерируется, в БД только `world_chunks`/seed |
| Двери (open/locked/hp) | симуляция | `world_doors` |
| Разрушенные пропсы | симуляция | `world_props` |
| Контейнеры и их лут | ленивая генерация | `world_containers`, `container_items` |
| Зомби (позиция, hp, alive) | симуляция | `world_zombies` |
| Игроки, позиция, статы | симуляция | `characters` |
| Инвентарь | транзакции | `character_items`, `ground_items` |
| События | аудит | `world_events` (не критично для восстановления) |
| Мета мира | старт | `world_meta` (`world_seed`) |

После рестарта сервер заново генерирует статическую карту по seed, применяет состояния дверей/пропсов, загружает зомби, лут на земле и персонажей. Персонажи без активного сокета не загружаются в память (только их данные в БД); при входе создаётся сущность.

### Поведение мира без игроков

- Тик симуляции продолжает идти, но голод/жажда и AI зомби обновляются только для онлайн-игроков; зомби вне радиуса 48 тайлов от игроков не симулируются.
- Лут не респавнится, зомби не респавнятся после смерти (в этой версии).
- Контейнеры не «сбрасываются» при отсутствии игроков.
- Смерть/дроп игрока сохраняются; respawn обрабатывается при следующем онлайне или по таймеру, если игрок ещё подключён.
- World seed нельзя менять без очистки БД: сервер сравнивает `world_meta.world_seed` и падает с понятной ошибкой.

## 4. Серверный цикл

`Simulation.start()`:

- `setInterval` 1000/TICK_HZ → `tick(1/TICK_HZ)`.
- `setInterval` 1000/SNAPSHOT_HZ → `broadcastSnapshots()`.
- `setInterval` 8 с → `saveAll()` (персонажи + зомби; предметы/двери/пропсы пишутся в момент изменения).

### Тик

1. Игроки: удаление отключённых после grace 25 с; respawn по таймеру; движение из последнего ввода; выносливость; голод/жажда; урон от истощения; регенерация.
2. Зомби: активны, если ближайший игрок в 48 тайлах; LOS-проверка раз в 350 мс; преследование/атака; блуждание; выталкивание из безопасной зоны; сохранение состояния.
3. Каждые 900 мс — проверка подписки на чанки; при смене чанка отправляются новые и выгружаются дальние.

### Снимки

Каждому клиенту отправляются только сущности в AOI (28 тайлов): другие игроки, зомби, предметы на земле, события с координатами. События без координат (чат, notice) получают все. Снимок содержит `self` (включая ack последнего input), `players`, `zombies`, `items`, `events`, `online`.

### Ввод и авторитетность

Клиент шлёт `input` 20 раз/с: `{mx,my,aim,sprint,seq}`. Сервер нормализует вектор, ограничивает скорость константами, двигает через `moveCircle` и общую коллизионную сетку, обновляет `lastAck`. Клиент не может телепортироваться, потому что его координаты не принимаются.

### Предсказание и коррекция

- Клиент ведёт `predicted` позицию той же физикой и общей сеткой коллизий, собранной из чанков и состояния дверей.
- На снимке: если ошибка > 1.15 тайла — жёсткая коррекция; если игрок стоит и ошибка > 0.05 — мягкая (20%); при движении мелкие расхождения игнорируются, чтобы не было «резинки».
- Чужие игроки/зомби сглаживаются экспоненциально к последнему снимку; при телепорте (>2.2 тайла) — snap.

## 5. Интерес и чанки

- `CHUNK_RADIUS=1` → клиент получает 3×3 чанка вокруг себя, выгружает дальше чем radius+1.
- Сервер отправляет чанк один раз на соединение (per-player `sentChunks`) и `chunk_unload` при выходе за радиус.
- При потере соединения клиент переподключается, сервер снова присылает welcome и чанки; существующие чанки в клиенте заменяются (старый `ChunkView.destroy()`, новый build).
- Сервер не загружает весь мир в клиент; AOI сущностей меньше, чем область загруженных чанков.

## 6. Клиентский рендер

- `GameScene` создаёт процедурные текстуры, атласы и анимации в `create()`.
- Земля: каждый чанк запекается в 2D canvas (2112×1056) и загружается как одна текстура, затем `Image` с глубиной `-1e6`.
- Объекты: отдельные `Image` с `depth = baseX+baseY` (изометрия). Стены — кубические спрайты 64×88, крыши — ромбы на высоте 56 px, персонажи — атлас 3072×1408.
- Скрытие крыш: если игрок внутри здания, крыша текущего здания плавно уходит в alpha 0.04, стены/двери/вывеска — в 0.32; при выходе восстанавливаются.
- Коллизии клиента: `ClientWorld.rebuildCollision()` собирает стены, блокирующие пропсы и закрытые двери из всех загруженных чанков.
- Миникарта: 2 px/тайл, базовый слой обновляется при загрузке чанка; маркеры игроков/зомби/предметов.
- HUD — DOM поверх canvas; ввод блокируется при открытом инвентаре/чате.

## 7. Бой и смерть

- Оружие: кулаки, бита, нож, лом, топор, пистолет. Урон/дальность/кулдаун — в `ITEMS`.
- Атака обрабатывается на сервере: проверка кулдауна, оружия, патронов, дуги/дистанции, для дальнего боя — LOS. Цели: игроки, зомби, затем разрушаемые пропсы.
- Пистолет тратит патроны из инвентаря транзакционно; шум привлекает зомби.
- Смерть игрока: полный дроп `character_items` в `ground_items` одной транзакцией, статус dead, `dead_until=+9 с`, смерть события; авто-respawn на спавне с пустым инвентарём. Убийца получает +1 kill.
- Смерть зомби: удаление из памяти, `world_zombies.alive=false`, шанс дропа.
- Трупы — визуальные временные спрайты (не сохраняются).

## 8. Инвентарь и транзакции

- Ёмкость: 26 кг, 24 слота; стаки по определениям предметов.
- Операции: pickup/drop/transfer/use/equip — сервер, с проверкой расстояния/владения/веса.
- Перенос предметов использует `SELECT ... FOR UPDATE`, поэтому два игрока не могут забрать один и тот же стек.
- Подбор: `DELETE ground_items ... RETURNING` + вставка в `character_items` в одной транзакции; повторный запрос получает null.
- Дубликаты seq отсекаются (`lastSeq` по типу действия), idempotency на уровне команд.
- При смерти и дропе предметы получают новые UUID; исходные строки удаляются. Дропается каждый стек отдельной записью.

## 9. Аутентификация и сессии

- HTTP `POST /api/auth/register|login|guest`, `GET /api/me`.
- Пароли: scrypt N=16384, r=8, p=1, соль 16 байт; формат `s1$salt$hash`.
- Токен: 32 случайных байта base64url; в БД хранится SHA-256, не сам токен.
- WebSocket auth — первое сообщение `{t:'auth', token, v}`; таймаут 8 с; проверка срока сессии.
- Сессии живут `SESSION_TTL_HOURS` (по умолчанию 168 ч).
- Rate limit auth по IP; WS — token bucket на соединение.
- Клиент хранит токен в `localStorage` (прототип; для продакшена — предпочтительнее HttpOnly cookie + CSRF).

## 10. Ошибки и восстановление

- `settle`/grace: при обрыве сущность игрока остаётся в памяти 25 с, чтобы reconnect не создавал второго персонажа; затем сохраняется и удаляется.
- Смерть и инвентарь пишутся в БД до ответа/события; при ошибке БД клиент получает notice, а сервер не подтверждает операцию.
- При падении сервера до периодического сохранения возможна потеря последних секунд позиции/статов, но не дублирование предметов: критичные операции уже в транзакциях.
- При смене seed/несовпадении меты сервер не стартует — защита от «полумира».
- Миграции идемпотентны (таблица `schema_migrations`).

## 11. Расширение

- Новые предметы: `ITEMS`, `LOOT_TABLES`, иконка в `client/src/art/textures.ts`.
- Новые пропсы: серверная генерация + текстура + anchor в `ART_PIPELINE`.
- Новые типы зомби: `ZOMBIE_TYPES`, скин в `ZOMBIE_STYLES`, веса спавна.
- Новые чанки/карта больше 128: изменить константы и генератор; сетевая архитектура уже чанковая.
- Новые действия: добавить сообщение в `shared/protocol.ts`, обработчик в `Simulation`, событие в snapshot, UI.
- Полноценный anti-cheat/реплеи: отдельный сервис/телеметрия; текущий сервер — необходимый, но не достаточный барьер.

## 12. Известные архитектурные компромиссы

- Один процесс и один мир; нет шардирования и горизонтального масштабирования.
- Зомби хранятся все в памяти (127), симулируются только активные; для больших миров нужна ленивая загрузка по чанкам.
- Клиентская коллизия доверяет данным чанков; сервер всё равно пересчитывает.
- HTML HUD и Phaser canvas живут раздельно; координация через методы HUD.
- Процедурная графика ограничена Canvas 2D и стилизована; фотореализм не заявлен.

# Дорожная карта

## Этапы из исходного задания

| Этап | Статус | Комментарий |
|---|---|---|
| 1. Рабочий каркас | ✅ | client/server/shared/PostgreSQL/Docker/CI, запуск, health, auth |
| 2. Визуальный вертикальный срез | 🟡 | изометрия, город, персонажи, глубина, крыши; VIS-01/02 не доведены |
| 3. Сетевой мультиплеер | 🟡 | серверная архитектура готова; E2E на двух клиентов отсутствует |
| 4. Бой и зомби | ✅/🟡 | серверный бой, PvP, зомби, смерть; нет полной E2E-проверки PvP |
| 5. Инвентарь и сохранения | ✅/🟡 | транзакции, лут, контейнеры, БД; нужен тест рестарта |
| 6. Устойчивость | 🔴 | unit-тесты есть; нет E2E, нагрузочных, полного аудита |

Обозначения: ✅ реализовано и проверено; 🟡 есть код, проверка неполная; 🔴 не сделано.

## P0 — до следующего демо

1. **VIS-01. Убрать сетку на земле.**
   - Уменьшить/убрать AO-градиент в `makeGround`.
   - Проверить стыки в атласе (padding/bleed).
   - Скриншот до/после, сравнение.
2. **VIS-02. Плотность и высота города.**
   - Приблизить угловые здания к перекрёстку; добавить витрины/навесы.
   - Поднять визуальную высоту стен (72–84 px), добавить парапеты/трубы/лестницы.
   - Убрать дубли вывесок на границах чанков.
   - Zoom 1.28–1.4, настроить follow offset.
3. **PERF-01. Старт без блокировки.**
   - Строить чанки по одному вне главного потока/с прогрессом.
   - Профилировать на реальном GPU; цель <5 с до интерактивности.
   - Рассмотреть Web Worker/OffscreenCanvas для ассетов.
4. **TEST-01. E2E на двоих + рестарт.**
   - Playwright contexts, движение, PvP, лут, рестарт, reconnect.
   - Сохранять скриншоты и JSON-отчёт.
5. **Docker smoke.**
   - Чистая машина: `docker compose up -d --build`; health; вход; скриншот.

## P1 — геймплей и надёжность

- Полноценная перезарядка пистолета (действие, анимация, патроны в магазине).
- Оружие: прочность/износ, разные типы патронов, дробовик/винтовка как расширение.
- Шум: индикатор, привлечение зомби шагами/выстрелами, порог.
- Зомби: респавн/миграция между чанками, удары по дверям, разрушение баррикад, special-типы.
- Баррикады/окна/ремонт; использование ткани/металлолома.
- Более развитый лут: редкость, шансы, контейнеры с несколькими отделениями.
- UI: журнал событий с фильтрами, подсказки, настройки графики/звука, сенситивность.
- Сохранения: тест краша, миграции, бэкапы, retention событий.
- Безопасность: Origin allowlist, TLS, cookies/CSRF, лимиты соединений, аудит зависимостей.
- Reconnect UX: сохранить открытый контейнер, восстановить чат/лог.
- Смерть: экран причины, статистика убийств/смертей, таймер точнее.
- Мультиплеер: сглаживание, экстраполяция, лаг-компенсация для стрельбы.

## P2 — контент и мир

- Расширение карты за 128×128 без изменения архитектуры (динамическая подгрузка).
- Больше типов зданий: многоэтажки, склады, АЗС, школа, больница, метро.
- Интерьеры с несколькими комнатами, лестницы/второй этаж (визуально и по коллизиям).
- Разрушаемость: стены, окна, машины, взрывы.
- Транспорт (вождение) — большой отдельный этап.
- NPC/торговцы? Только после вертикального среза и стабильности.
- Погода/время суток/освещение/фонарики.
- Крафт (бинты, баррикады), готовка/вода.
- Квесты/ивенты — не раньше, чем мир станет устойчивым.
- Монетизация/аккаунты/античит — отдельный прод-этап.

## Принципы приоритизации

1. Сначала то, что ломает впечатление от вертикального среза (визуал, старт, сеть).
2. Затем то, что ломает доверие к сохранениям (дубли, рестарт, гонки).
3. Только потом контент и «фичи».
4. Любая новая механика должна иметь серверную проверку и тест.
5. Не расширять карту/контент, пока базовый район не выглядит цельно.

## Разделение работы с локальной моделью

Локальный Claude/Gemini в Antigravity может параллельно делать:

- визуальный аудит скриншотов и предложения по палитре/композиции;
- Playwright E2E сценарии и их отладку;
- ревью серверных транзакций и гонок;
- генерацию вариантов контента (имена зданий, тексты, лут-таблицы) с последующей проверкой;
- unit-тесты для чистых функций.

Не отдавать без ревью: миграции БД, протокол, безопасность, денежные/аккаунтные операции. Любые изменения — через PR и проверки из `docs/TESTING.md`.

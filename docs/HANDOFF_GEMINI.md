# Handoff: продолжение разработки ASHFALL

Документ для следующего агента/разработчика (Gemini в Antigravity, Claude Opus, человек). Цель — продолжить проект без потери контекста и без ложных заявлений о готовности.

## 0. Роль и главное правило

Ты продолжаешь **рабочий прототип браузерной многопользовательской survival-игры** на Phaser 3 + Node.js + PostgreSQL.

- Не переписывай движок и не создавай параллельную реализацию.
- Не объявляй функцию готовой, пока не собрал проект и не проверил сценарий.
- Сначала прочитай `docs/STATUS.md`, `docs/ARCHITECTURE.md`, `docs/PROTOCOL.md`, `docs/TESTING.md`, `AGENTS.md`.
- Все изменения — через ветку и PR; CI должен быть зелёным.
- Не коммить секреты. `.env` в `.gitignore`; используй `.env.example`.

## 1. Что уже сделано (кратко)

- Монорепо: `client` (Phaser 3.90/TS/Vite), `server` (Node/ws/pg), `shared` (протокол/физика/константы).
- Авторитетная симуляция 20 Гц, снимки 12 Гц, AOI 28 тайлов, 3×3 чанка.
- Мир 128×128, 16 чанков, детерминированная генерация города.
- PostgreSQL: аккаунты, сессии, персонажи, предметы, контейнеры, двери, пропсы, зомби, чанки, события.
- Бой (ближний/пистолет), PvP, зомби 3 типов, смерть/лут/респавн, инвентарь 26 кг/24 слота, контейнеры.
- Процедурная графика: тайлы, стены, крыши, машины, деревья, мебель, персонажи (7 стилей), UI, миникарта, звук.
- Безопасная зона на спавне; стартовый набор; guest-вход.
- Docker Compose, CI, unit-тесты (10), Playwright visual-тест.

Подробный и честный список: `docs/STATUS.md`.

## 2. Что НЕ сделано (не выдавай за готовое)

- Визуальный вертикальный срез не доведён: тёмные швы тайлов (VIS-01), город пустоват/плоский (VIS-02).
- Нет E2E на двух клиентов, PvP и рестарт сервера не проверены сквозным тестом.
- Docker Compose не проверен на чистой машине.
- Нет полноценной перезарядки (патроны списываются автоматически).
- Нет баррикад/окон/ремонта, респавна зомби, вождения, крафта.
- Нет TLS/Origin allowlist/полноценного античита.
- Звук и мобильная вёрстка не проверены.

## 3. Требования к локальному окружению

- Node.js 22+ (проект проверен на 22.23.3), npm 10+.
- Docker + Docker Compose (PostgreSQL 16). Если Docker недоступен, установите PostgreSQL 16 локально и задайте `DATABASE_URL`.
- Chromium для Playwright (`npx playwright install chromium` или системный Chrome; путь можно задать `CHROMIUM_PATH`).
- ОС: Linux/macOS; Windows — через WSL2 рекомендуется.
- 4+ ГБ RAM, 2+ CPU. GPU желателен: игра рендерится через WebGL, но Phaser может откатиться на Canvas (медленнее).

### Клонирование и запуск (Docker)

```bash
git clone git@github.com:z-horror/ashfall.git
cd ashfall
cp .env.example .env
docker compose up -d --build
# http://localhost:8080
```

Если Docker-путь не работает, зафиксируй ошибку в issue/PR и используй локальный:

```bash
cp .env.example .env
npm ci
docker compose up -d db      # или локальный PostgreSQL
npm run migrate
npm run dev                  # http://localhost:5173
```

Порты: клиент 5173 (dev) / 8080 (Docker), сервер 3000, PostgreSQL 5433.

### Сброс мира

```bash
docker compose down -v
docker compose up -d db
npm run migrate
```

Мир детерминирован от `WORLD_SEED`. Менять seed можно только с очисткой БД: сервер сравнивает `world_meta.world_seed` и откажется стартовать при несовпадении.

## 5. P0 задачи

### P0-1. VIS-01: убрать тёмную сетку на земле

**Файл:** `client/src/art/textures.ts`, функция `makeGround` (в конце).

Сейчас на каждом тайле рисуется вертикальный градиент:

```ts
const ao = ctx.createLinearGradient(0, 0, 0, 32);
ao.addColorStop(0, 'rgba(0,0,0,0.2)');
...
ao.addColorStop(1, 'rgba(0,0,0,0.26)');
```

На стыках это даёт регулярную тёмную сетку.

**Сделай:**
1. Убери этот градиент или снизь alpha до 0.02–0.05.
2. Проверь, что базовый ромб рисуется с запасом (сейчас `diamondPath(..., 66, 34, -2)`), но атлас может «подсасывать» соседние пиксели. Добавь 2 px padding вокруг каждой текстуры в `packEnvironmentAtlas` или рисуй тайлы с `ctx.imageSmoothingEnabled=false` при запекании.
3. По желанию добавь лёгкую вариативность: разные края (трещины/пятна), но без регулярной сетки.
4. Пересобери и сделай скриншот `screenshots/01-world.png`; приложи до/после в PR.
5. Проверь стыки на асфальте, тротуаре, траве, деревянном полу.

**Критерий:** нет видимой регулярной сетки; покрытие читается как единая поверхность; нет ярких швов/bleed.

**Подсказка:** можно временно экспортировать атлас (`node tools/export-atlas.mjs`) и посмотреть `env_atlas.png`, чтобы увидеть, есть ли bleed.

### P0-2. VIS-02: плотность и высота города

**Файлы:** `server/src/game/world.ts` (генерация), `client/src/world/chunkView.ts` (рендер), `client/src/game/GameScene.ts` (камера/fade), `client/src/art/textures.ts` (стены/крыши/декор).

**Проблемы:**
- У перекрёстка мало зданий в кадре; блоки большие, застройка отступает.
- Здания выглядят как одноэтажные коробки; крыши плоские.
- Вывески могут дублироваться на границах чанков.
- Обзор слишком широкий (zoom 1.14), персонаж мелкий.

**Сделай (в таком порядке):**
1. Подними zoom до 1.28–1.4, настрой `setFollowOffset` (сейчас 0,34), проверь обзор на 1600×900 и 1280×720.
2. Уплотни застройку у перекрёстков: добавь угловые здания ближе к тротуару, витрины/навесы, больше мелких объектов. Не ломай коллизии и двери.
3. Подними визуальную высоту стен с 56 до 72–84 px. Это потребует синхронно поправить `WALL_HEIGHT`, позиции крыш/вывесок и `ChunkView` (крыша = `p.y - WALL_HEIGHT`). Проверь, чтобы персонаж не «утопал» и крыши не перекрывали улицу.
4. Добавь парапеты/трубы/антенны/вентиляцию/пожарные лестницы на крыши; вывески ставь только из чанка, содержащего дверь (сейчас `buildRoofs` добавляет вывеску из каждого чанка здания).
5. Добавь мелкий декор: лужи, листья, объявления, провода, урны, скамейки, конусы, кирпичи. Держи единую палитру и масштаб.
6. Проверь скрытие крыш при входе в здание и глубину: персонаж за деревом/стеной/машиной, южнее здания — поверх крыши.

**Критерий:** скриншот улицы у спавна выглядит как плотный городской квартал, а не пустое поле; нет дублей вывесок; вход в здание читается.

### P0-3. PERF-01: старт без долгой блокировки

**Файлы:** `client/src/game/GameScene.ts` (`create`, `applyChunk`), `client/src/art/*`, `client/src/world/chunkView.ts`.

**Факты (headless SwiftShader):** env art ~12.4 с, char art ~9.7–13 с, чанк 1–2.4 с, 9 чанков ~14 с. На реальном GPU не измерено.

**Сделай:**
1. Замерь на целевом железе с аппаратным WebGL (Chrome, devtools performance).
2. Если старт > 5 с:
   - строй чанки по одному в `requestAnimationFrame`/`setIdleCallback`, показывай прогресс в loading screen;
   - не блокируй UI: welcome → показать HUD, затем чанки;
   - рассмотри Web Worker + OffscreenCanvas для генерации текстур;
   - проверь, не является ли узким местом загрузка 2112×1056 текстур (уменьшить разрешение/масштаб тайлов, кэшировать).
3. Не ухудшай качество графики ради цифр без измерения.
4. Запиши результаты в `docs/STATUS.md`.

**Критерий:** первый интерактивный кадр < 5 с на среднем ПК; нет фризов > 100 мс при переходе между чанками; нет ошибок в консоли.

### P0-4. TEST-01: E2E на двух клиентов и рестарт

**Файл:** `tools/e2e-multiplayer.mjs` (создать), можно использовать `playwright-core`.

Сценарий:
1. Два контекста, оба guest-логин.
2. Проверить, что каждый видит второго в snapshot/мире (можно через `window.__ashfall`).
3. Движение A → B видит изменение координат/позиции.
4. A атакует B → HP B падает; при смерти B появляется лут.
5. Оба пытаются взять один предмет → ровно один получает.
6. Контейнер: A открывает, B открывает; нельзя взять один стек дважды.
7. `docker compose restart server` → оба переподключаются; позиция/инвентарь/лут/двери/зомби восстановлены.
8. Скриншоты + JSON-отчёт в `screenshots/e2e/`.

**Критерий:** сценарий проходит локально и в CI (CI может ограничиться сборкой; E2E — отдельная job с Postgres service).

## 8. Правила кода

- TypeScript strict; не отключай проверки без причины.
- Общие типы/константы — только в `shared`; не дублируй значения.
- Сервер — единственный источник истины. Любая новая механика должна проверяться на сервере.
- Критичные операции с предметами/смертью — `withTransaction` + `FOR UPDATE`.
- Не добавляй зависимости без необходимости; проверяй лицензии и размер бандла.
- Не коммить `node_modules`, `dist`, `.env`, секреты, большие временные файлы.
- Комментарии — только там, где они объясняют неочевидное; код должен читаться.
- Соблюдай стиль существующих файлов (2 пробела, одинарные кавычки, trailing comma).
- Новые сетевые сообщения: Zod-схема, обработчик, событие/snapshot, документация, тест.
- Миграции БД — только новые файлы `002_...sql`; не редактируй применённые.
- Не меняй `WORLD_SEED` в коммитах.

## 9. Git и PR

- Ветки: `fix/...`, `feat/...`, `docs/...`, `test/...`.
- Маленькие атомарные коммиты; сообщения в императиве, например:
  - `fix(art): remove per-tile AO seams`
  - `test(e2e): verify two-client sync and loot`
- Перед PR: `npm run typecheck && npm test && npm run build`.
- В PR: что изменено, как проверено, скриншоты до/после, риски, обновлённые документы.
- Не force-push в main. Не мерж без зелёного CI.
- Секреты/токены — только в локальном `.env`.

## 11. Отладка типовых проблем

| Симптом | Что проверить |
|---|---|
| Сервер не стартует: seed mismatch | `world_meta.world_seed` vs `.env`; сбросить БД или вернуть seed |
| Guest 500 | логи сервера; чаще всего ошибка SQL/транзакции; проверить миграции |
| Клиент пустой, нет чанков | WS статус, `applyChunk`, `CHUNK_RADIUS`, ошибки в консоли |
| Персонаж «резинит» | predicted vs snapshot, клиентская коллизия, закрытые двери, лаг |
| Не открывается дверь/контейнер | дистанция, id, seq, `open_container`; проверить `world.doors/containers` |
| Лут дублируется | транзакции, `FOR UPDATE`, `DELETE RETURNING`; логи `[sim]` |
| После рестарта мир другой | seed/БД volume; `docker compose down -v` |
| Тёмная сетка земли | VIS-01; AO/bleed в атласе |
| Низкий FPS | draw calls, число объектов, размер текстур, software WebGL |
| Playwright зависает | loading selector; использовать `waitForFunction`; увеличить timeout; проверить GPU flags |
| `char_atlas` not found | атлас создаётся до анимаций; проверить `buildCharacterAssets` |
| Вывески дублируются | ставить только из чанка с дверью |

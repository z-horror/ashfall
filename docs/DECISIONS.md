# Ключевые решения (ADR-lite)

## D1. Phaser 3 + TypeScript + Vite

- **Решение:** Phaser 3.90, TS strict, Vite.
- **Почему:** требование задания, зрелая изометрия/спрайты/камера, быстрый dev-цикл.
- **Цена:** Phaser тянет ~1.3 МБ JS; кастомный рендер не нужен на этом этапе.

## D2. Процедурная графика вместо набора PNG

- **Решение:** тайлы/стены/пропсы/персонажи генерируются Canvas 2D при старте; key art — FLUX.
- **Почему:** единый масштаб/освещение/палитра, нет проблем с лицензиями и несогласованными ассетами, легко менять.
- **Цена:** генерация на клиенте, большой код арта, сложнее достичь фотореализма.
- **Смягчение:** атласы, изоляция в `client/src/art`, экспорт атласов для ревью.

## D3. Авторитетный сервер, клиент — только ввод

- **Решение:** сервер считает всё; координаты клиента не принимаются.
- **Почему:** честность, античит-минимум, консистентность.
- **Цена:** задержка; нужна интерполяция и предсказание.

## D4. Общая физика в shared

- **Решение:** `moveCircle`/LOS/конус в `shared`, используются обеими сторонами.
- **Почему:** предсказание совпадает с сервером, меньше рассинхрона.
- **Цена:** клиентская коллизия зависит от загруженных чанков; при переходе в незагруженную зону предсказание может временно расходиться.

## D5. Постоянный мир: статика от seed, динамика в БД

- **Решение:** карта детерминирована; в БД только изменения и сущности.
- **Почему:** не хранить 16k тайлов и зданий, быстрый рестарт, простая миграция.
- **Цена:** смена seed требует очистки; изменения генератора меняют мир (нужна версия/миграция при необходимости).

## D6. Чанки + AOI, LOD зомби

- **Решение:** 3×3 чанка клиенту, сущности в 28 тайлах, AI зомби в 48 тайлах.
- **Почему:** масштабирование и трафик; не симулировать весь мир.
- **Цена:** зомби за пределами радиуса «спят»; возможны телепорты восприятия при приближении (сглаживаются).

## D7. PostgreSQL + транзакции для инвентаря

- **Решение:** `FOR UPDATE`, `DELETE RETURNING`, ленивая генерация лута, write-through.
- **Почему:** защита от дублей и гонок; требование ТЗ.
- **Цена:** БД на критичном пути; при недоступности БД операции не проходят (это правильно).

## D8. Аутентификация собственная (scrypt + opaque tokens)

- **Решение:** без OAuth/платежей; гостевой вход для тестов.
- **Почему:** самостоятельный прототип без внешних сервисов.
- **Цена:** нет восстановления пароля/2FA; токен в localStorage; для прода — cookie/CSRF.

## D9. Один процесс — один мир

- **Решение:** симуляция в памяти одного Node-процесса; БД общая.
- **Почему:** простота и скорость разработки.
- **Цена:** нет горизонтального масштабирования; при нескольких инстансах нужна блокировка/шардирование.

## D10. HTML/CSS HUD вместо Phaser UI

- **Решение:** DOM поверх canvas.
- **Почему:** быстрый, доступный, легко стилизовать; инвентарь/чат/логи удобнее.
- **Цена:** координация ввода/фокуса (блокировка при открытых панелях), два слоя.

## D11. Один мир без инстансов и лобби

- **Решение:** все в общем мире, PvP всегда включён.
- **Почему:** требование «постоянный мир» и свободный PvP.
- **Цена:** грифтинг; нужна безопасная зона (уже есть) и, возможно, механики репутации позже.

## D12. Ошибки и деградация

- **Решение:** сервер не стартует при несовпадении seed; клиент переподключается; операции с БД не подтверждаются при ошибке.
- **Почему:** лучше явный отказ, чем «полумир» с дублями.
- **Цена:** при смене seed нужна ручная очистка; при БД-аварии игра недоступна (ожидаемо).

# AGENTS.md — правила для агентов в репозитории ASHFALL

Ты работаешь над приватным прототипом браузерной изометрической zombie-survival игры. Цель — довести вертикальный срез до цельного вида и подтверждённой стабильности, а не написать как можно больше кода.

## 1. Перед любыми изменениями

1. Прочитай:
   - `docs/STATUS.md` — что реально проверено и что сломано;
   - `docs/ARCHITECTURE.md` — устройство;
   - `docs/PROTOCOL.md` — сетевые сообщения;
   - `docs/TESTING.md` — как проверять;
   - `docs/HANDOFF_GEMINI.md` — текущие задачи P0/P1;
   - `docs/ART_PIPELINE.md` — если трогаешь графику.
2. Воспроизведи baseline:
   ```bash
   npm ci
   npm run typecheck
   npm test
   npm run build
   ```
3. Запусти проект и убедись, что видишь мир:
   ```bash
   cp .env.example .env   # если ещё нет .env
   docker compose up -d db
   npm run migrate
   npm run dev
   ```
4. Создай ветку: `fix/...`, `feat/...`, `test/...`, `docs/...`.

## 2. Незыблемые правила

- **Сервер авторитетен.** Не доверяй клиентским координатам, урону, луту, инвентарю, результатам боя.
- **Не переписывай движок** (Phaser 3 + Node + PostgreSQL) и не создавай параллельную реализацию.
- **Не объявляй функцию готовой без проверки.** Запускай сборку/тесты/браузер.
- **Не коммить секреты**, `.env`, токены, ключи, персональные данные. Используй `.env.example`.
- **Не меняй `WORLD_SEED`** без явного решения и очистки БД.
- **Не редактируй уже применённые миграции.** Только новые `database/migrations/NNN_*.sql`.
- **Не ломай протокол без версии.** Несовместимое изменение → `PROTOCOL_VERSION++` + документация + обе стороны.
- **Критичные операции с предметами/смертью — транзакции** (`withTransaction`, `FOR UPDATE`).
- **Не добавляй платные/внешние API** для базового запуска.
- **Не трогай чужие проекты** за пределами этой папки.
- Один процесс сервера = один мир; не пытайся запускать несколько инстансов против одной БД.

## 3. Проверки перед PR

```bash
npm run typecheck
npm test
npm run build
npm run test:visual   # если менял клиент/графику; нужен запущенный dev-стек
```

Требования:

- 0 ошибок типов, 0 падений тестов, успешный build.
- Нет новых ошибок в консоли браузера (кроме известных внешних 404).
- Для визуальных правок — скриншоты до/после.
- Для сетевых/БД — сценарий воспроизведения и логи.
- Обновлены `README`/`STATUS`/`PROTOCOL` при необходимости.

## 4. Текущий приоритет (не начинай с другого)

1. `VIS-01` — убрать тёмную сетку/швы земли.
2. `VIS-02` — плотность и высота города, камера, отсутствие дублей вывесок.
3. `PERF-01` — не блокировать старт; измерить на реальном GPU.
4. `TEST-01` — E2E на двух клиентов + рестарт сервера.
5. Docker smoke на чистой машине.

Детали и критерии — `docs/HANDOFF_GEMINI.md`.

## 5. Стиль кода

- TypeScript strict, ES modules, 2 пробела, одинарные кавычки, trailing comma.
- Общие типы/константы/физика — в `shared`, не дублировать.
- Серверные модули: `server/src/{game,net,persistence}`; клиентские: `client/src/{art,game,net,ui,world}`.
- Не создавай файлы на тысячи строк; разделяй по ответственности.
- Комментарии — только для неочевидных решений.
- Новые зависимости — обоснованно, с проверкой лицензии/размера; обновляй lock-файл.
- Новые предметы: `shared/src/constants.ts` (`ITEMS`, `LOOT_TABLES`), иконка/текстура в art, при необходимости серверная логика.
- Новые пропсы: генерация в `server/src/game/world.ts`, текстура/anchor в art, рендер в `ChunkView`.
- Новые сетевые сообщения: Zod-схема в `shared/src/protocol.ts`, обработчик в `Simulation`, событие в snapshot, документация, тест.

## 6. Git

- Ветки от `main`; не пушь напрямую в `main`.
- Атомарные коммиты; стиль: `fix(art): remove per-tile AO seams`, `test(e2e): two-client sync`.
- PR: что/зачем/как проверено/скриншоты/риски.
- Не мержи без зелёного CI. Не force-push в `main`.
- Секреты — только локальный `.env` (игнорируется).

## 7. Работа с локальной моделью (Gemini/Claude)

- Разделяй работу по файлам, чтобы избежать конфликтов: визуал (`client/src/art`, `chunkView`, `GameScene`) и сеть/тесты (`server`, `tools`, `server/test`, CI).
- Передавай агенту ровно одну задачу + критерий приёмки + список файлов.
- Требуй baseline-отчёт и доказательства (скриншоты/логи/метрики).
- Не делегируй без ревью: миграции, протокол, безопасность, seed/карта, деплой/секреты.
- Готовый промпт — в `docs/HANDOFF_GEMINI.md`, раздел 10.

## 8. Если сломалось

- Сначала прочитай логи: `[sim]`, `[db]`, `[ws]`, `[auth]`, console браузера.
- Проверь `/api/health`, WS статус, `world_meta.world_seed`.
- Если мир не совпадает с БД — не меняй seed наугад, сбрось volume осознанно (`docker compose down -v`).
- Если не уверен — оставь issue/TODO с воспроизведением, не прячь ошибку за заглушкой.
- Никогда не заявляй, что запускал команду/браузер/тест, если фактически не запускал.

## 9. Definition of Done

- Код собирается, типы и тесты зелёные.
- Сценарий задачи проверен в браузере/на сервере; есть доказательство.
- Нет новых критичных ошибок, дублей предметов, утечек секретов.
- Документация обновлена; известные ограничения записаны.
- PR готов к ревью человеком.
